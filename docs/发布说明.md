# 发布说明

## 版本与流程

使用 `主版本.次版本.修订号` 格式，当前 `0.x` 为预览阶段。版本标签形式为 `v0.1.0`。发布版本必须与 `version.txt`、`package.json` 和锁文件保持一致。

1. 更新版本、`CHANGELOG.md` 与 `RELEASE_NOTES.md`。
2. 运行 `npm test` 和 `build.ps1`，审阅改动及兼容说明。
3. 检查源码和产物中是否有个人信息、电脑信息、凭据、日志或不应发布的资源。
4. 将经过审阅的提交合入 `main`，确认 CI 通过。
5. 为该提交创建并推送 `v*` 标签。
6. 标签发布流程再次调用完整 CI，上传 ZIP 与 SHA-256 文件，最后公开预览版 Release。

已公开版本的附件不自动覆盖。出现发布失败时先检查是否留下草稿，确认附件完整后再处理；不要在未审查的情况下替换已公开的文件。

## 产物

- `antigravity-chinese-companion-v<版本>-windows.zip`
- `SHA256SUMS.txt`
- GitHub 自动提供的标签源码压缩包

Windows ZIP 包含主程序、独立恢复工具、使用说明和 MIT 许可证。EXE 从标签对应的公开源码构建，默认无调试符号。当前没有代码签名或可复现构建承诺。

## 发布隐私

项目使用项目或贡献者署名，仓库只接收明确列入发布清单的文件。不包含本机路径、个人账户配置、客户端原始资源或会话记录。不得把调试日志、原始截图或个人配置复制进发布包。

平台仍会展示仓库归属、公开活动和执行者等平台元数据；这不应成为在发布文件内加入额外个人信息的理由。
